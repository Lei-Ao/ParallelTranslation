# 翻译与排版性能验证（2026-11-08）

## 使用与回退

当前默认固定 3 并发、每批最多 3 段；下方历史对照中的 5 段是测试当时的基线。阅读菜单可分别启用自动组批和自动并发。提前排版默认开启，可取消勾选回退为结束后排版。模型、思考设置、术语表与翻译要求不因这些选项改变。

自动组批按同页阅读顺序处理，最多 12 块。初始 6,000 字符预算在真实测试中出现长响应拖尾，因此改为约 1,200 字符软预算，1,000 字符以上正文单独请求；单段仍受原有 18,000 字符上限约束。正文与参考文献分组，识别出的续句等待前段保存。响应缺失或无效时只重试相关块并缩小批次。自定义 HTTP 接口继续单段请求。

自动并发从 3 开始，连续 12 次无重试、无缺失请求后增加 1，最高 6；收到限流或连续两次超时减半，最低 1。支持秒数和 HTTP 日期形式的 Retry-After，不提前截短服务端等待。暂停停止新增请求和重试，已返回译文继续保存。

提前排版最多一个前端请求在途，每次最多准备两页；暂停取消未派发页面。服务端仍用 PDF 安全锁。页面必须全部具有当前目标语言译文才会预排版，最终按最新快照校验缓存并统一合并、恢复链接与目录。预排版失败由最终排版补做，不影响已保存译文。

## 本机实测

环境为 Windows、Python 3.12、锁定依赖；真实接口为 `https://api.deepseek.com`，模型 `deepseek-flash`，思考强度 `max`。测试在临时数据目录使用三份独立副本，未覆盖用户文档。

真实对照从一份 8 页论文选取相同的 23 个待译块（3,193 原文字符），其余内容使用相同已有译文。覆盖标题、作者、摘要、正文、图注、表内文本和图内短标签。每种策略只运行一次；请求没有发生重试。

| 策略 | 请求数 | 翻译阶段 | 翻译后的等待 | 总耗时 |
| --- | ---: | ---: | ---: | ---: |
| 固定 3 并发／5 段，结束后排版 | 7 | 20.57 秒 | 约 5.75 秒 | 约 26.32 秒 |
| 初始自动组批，提前排版 | 4 | 30.55 秒 | 1.39 秒 | 31.94 秒 |
| 调整后的自动组批，提前排版 | 6 | 14.76 秒 | 4.13 秒 | 18.89 秒 |

调整后本次总时间减少约 28%。基线首次导出的报告尚未计入最后排版，其总时间用服务端请求时间线补齐；后续已修复并加入最终耗时回归测试。第二、三轮总时间直接来自浏览器完整报告。

这不是整篇从零翻译的基准，也不是多次测量的稳定均值。网络、服务端负载、提示词缓存和模型输出变化都会影响结果，不能据此承诺其他论文也提升 28%。本次请求不足 12 次，真实测试未触发自动并发增档；该行为已通过模拟调度测试。自动模式因真实样本有限保留为可选项。

23 块均完整返回，逐块检查未见整段漏译、关键数字丢失或 ID 错配；措辞仍有变化，例如“稳定／镇定”“手工设计／手写”。此检查不等于专业译文质量认证，自动策略仍需结合专业术语和更多论文复核。

## 排版与兼容性

同一份保存译文在隔离目录比较：旧版首次排版约 5.97 秒，新版按页字体资源首次排版约 9.14 秒。逐页字体子集有额外首次开销，收益来自将页面准备与模型等待重叠，而非消除这部分计算。完成预排版后，最终合并约 0.17 秒；该数字不包含前面的预排版时间。

8 页新旧输出的可提取字符及链接目标一致，其中 6 页渲染像素完全一致。其余 2 页仅涉及公式后正文间距修正，已检查并排预览；新版本中串行与预排版输出逐页像素一致。295 个排版替换块、84 个保留原文块的统计未变，保留原文不代表这些区域已完成翻译排版。

修复了原有公式像素测试失败：正文重排需尊重原始公式的完整字体框，而不仅是较小的可见墨迹裁剪框。原严格像素断言保持不变。

缓存版本从 76 升至 77。原文、字体、目标语言、页面译文、续句信息和规范化版本参与身份计算。旧缓存保留但不复用为新版结果；文档 JSON 与段落 ID 不迁移。译文请求期间的人工编辑不会被迟到结果覆盖，过期排版不得发布成当前成品。

自动化验证覆盖单栏、双栏、不同尺寸、0／90／180／270 度旋转，以及现有标题、作者、图表、公式、参考文献和链接回归。新增串行／预排版对照比较文字与像素。真实论文目前仅验证一篇 8 页样本，其他版式主要由合成样本覆盖。

## 诊断与复现

阅读菜单可导出最近一次耗时报告。`total_ms` 为到最终排版完成的墙钟时间；`translation_ms` 为翻译阶段；`layout_tail_ms` 包含翻译完成后等待预排版收尾及最终合并的时间。`queue_ms`、`model_ms` 等为多个任务累计值，存在并行，不能相加当作总耗时。模型计时包含连接、网络传输和服务端等待。重试等待与限流等待分开记录。

后端 `tmp/performance.jsonl` 记录数字计时、计数与状态码，超过约 5 MB 轮转一份历史文件。没有密钥、接口请求正文、文档名称或译文正文。页面缓存命中、字体准备、排版、合并、保存分别计时。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test (Get-ChildItem tests/test_*.js).FullName
.\.venv\Scripts\python.exe tests/benchmark_pipeline.py --doc .data/<文档目录> --out tmp/<新的测试目录>
```

离线基准不调用模型、不改动原文档，输出目录必须不存在；它分别测量首次字体准备、完整缓存以及预排版后的合并。输出的 PDF 可用于逐页对照。此次修改前代码备份位于 `tmp/speed-baseline/`，实测原始文件位于 `tmp/live-speed-validation/` 与 `tmp/speed-before/`、`tmp/speed-after/`，均不进入源码分发。
