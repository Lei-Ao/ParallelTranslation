# 开发与排版说明

以下说明当前实现、回归范围与保守回退机制。有限样本通过不代表任意论文都已完成适配。

## 开发与验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
node --test tests/test_translation_queue.js tests/test_layout_updates.js tests/test_open_flow.js
python tests/audit_corpus_layout.py
```

测试覆盖 PDF 提取、旋转坐标、页面渲染、空白页、加密及损坏文件、接口请求与上下文、自定义响应、认证错误、超时、截断结果保护、译文存储与导出、本机访问保护。测试使用临时目录与模拟接口，不消耗真实 API 额度。

自动化测试使用临时生成的 PDF 和模拟接口。个人论文、译文、缓存和开发截图不随源码分发。真实模型的翻译质量需另行评估。

结构：`app.py` 为 FastAPI 后端、PDF 解析和 Agent 适配；`static/` 为无构建依赖的前端；`tests/` 为集成测试。无需 Node.js 即可运行，Node 仅用于可选 JS 语法检查。

排版回归还覆盖公式相邻解释、误并入正文的公式编号，以及两端对齐文字的误判。正文擦除使用字符内部的窄区域，并检查邻近字符，避免文字框的微小重叠导致整段被跳过；独立公式不与相邻解释合并。

排版以复刻原文布局为目标：在同栏安全区域内按原文实际的段间距、标题间距和公式间距连续排布，收回译文缩短造成的新增大块空白；保留图片、表格、图注位置及原文有意留白。独立公式可连同编号、上下标和分数线作为完整矢量区域一起移动，不能安全移动时保持原样。对齐方式由原文各行的左右边界和基线判断，正文不会仅因文本框靠近页面中轴就被居中；可识别的正文首行缩进也会保留。行距参考原文基线间距，中文优先使用较舒展的行距，并先尝试在安全区域内以原字号排印，无法容纳时再逐步收紧或缩小。中外文长度不同，译文行数和每行断句不保证与原文完全一致。

提取器把同一自然段切成相邻文本块时（常见于行末带行内公式的位置），排版会按同栏、左边界、行距、行末是否排满、下一块首行缩进和字号判断续段，合并后在原区域内排布；图注、标题、列表项、参考文献和表格不参与合并。图表避让使用 PDF 裁剪后可见的绘图范围，避免被隐藏的图形路径错误挡住另一栏正文。封面标题、作者及正文按几何位置和样式识别，不依赖特定论文的段落编号。章节编号与标题之间的矢量分隔线会随标题译文一并清除。可可靠匹配的结构化粗体标签保留半粗体。表格以表题定位为整块保留原文，只翻译表题与表注；双栏页面按栏切分后再识别表格。排版算法更新会使旧缓存失效，重新打开文档或重新排版即可使用新版，无需重新翻译。

回归覆盖不同字号、旋转页面、裁剪图形、作者信息、公式和参考文献。本地语料检查 `tests/audit_corpus_layout.py` 自动读取所有已有译文的文档，逐页检查译文字符、排版区域与保留文字的碰撞，以及调整后的间距是否符合原文参考值，并在 `tmp/source-layout-audit/` 输出报告及原文/译文页面预览；不修改译文、不调用翻译接口。有限样本通过不代表任意论文的复杂区域均已适配。

中文正文的行内数学符号会从原 PDF 中单独提取字形轮廓，按原始比例、上下标和基线参与换行，并按实际笔画高度预留行内空间。符号以高分辨率图像嵌入，附带不可见的原始译文拼写供搜索和复制；无法可靠匹配的符号继续使用文字回退。此方式避免将相邻行笔画截入符号，也避免排版完成后覆盖符号造成拉伸和重叠。

行内公式优先匹配完整表达式，再匹配独立变量，允许译文调整语序。基向量列表中的逗号变为顿号或连接词时，可按完整变量分别保留带帽符号和上下标；带运算符和函数参数的表达式不做这种拆分。缺字只对对应字符使用备用字体，空间不足时也优先保留正文的书体，避免整段突然变粗或变成无衬线字体。正文粗细按原文的主要文字样式确定，段首粗体标签单独映射。

公式字体框与相邻正文接触时，会进一步测量原始字形的实际笔画边界；只有确认不会裁字或碰到相邻内容，才允许公式连同编号一起移动，以减少字体框空白造成的排版阻挡。

单行图注、表注会根据原文与页面、栏或相邻图形的中心轴关系判断是否居中，原文左对齐的说明仍保持左对齐。中文译文中紧贴汉字的拉丁术语（例如 Hopf、JAX、BLCM）会在 PDF 排版时补充空格；不改写已保存的译文，已有空格、数字标签、网址、邮箱和行内代码保持原样。段落重排在能可靠分离文字绘制范围时匹配原文的可见字形间距，扣除中外文字体框内部空白差异；无法确定归属时继续使用原文本框间距。图表、公式和原文有意留白仍受原有避让约束。中文译文段落开头的项目符号按原文符号的字号和字重排印，避免中文字体把圆点画得过小；编号列表保持原样。此更新使用排版缓存版本 42，重新打开文档或重新排版即可生效，无需重新翻译。

常规字重或被提取成多块的标题行，依据页面正文字号层级及原文的页面、栏中心轴判断是否居中，不依赖论文名称、页码或粗体标记。相邻标题行共享左边缘或右边缘时，避免仅因第一行恰好铺满宽度而误判居中。对齐调整不改写已保存译文和段落标识；对齐信息不足的区域沿用已有保守规则。

首页居中的作者、单位和邮箱按完整信息区统一预排版，作者编号保留为上标，邮箱独立使用等宽字体；可用高度由下一段文字或插图确定，不再逐段向下偏移。生成后同时检查文字完整性和各行是否重叠。信息未译齐、包含无法安全移动的图形或整体无法容纳时，整组保留原文并提示，避免作者与单位被分别覆盖。

技术参考：[PyMuPDF 文本提取](https://pymupdf.readthedocs.io/en/latest/app1.html)、[FastAPI 文件上传](https://fastapi.tiangolo.com/tutorial/request-files/)。

首字下沉会根据装饰性首字的字体、相邻正文的字号、行首间距和绕排几何恢复完整单词，再发送至翻译接口；首字本身为独立词时，按原文词间距保留空格。可处理首字单独成块、混入上一标题或并入正文的情况；原 PDF 不变，正文段落 ID 保留，独立字母旧 ID 通过别名兼容，受影响的旧记录另存于文档数据的 `drop_cap_legacy`。旧正文译文保持不变，仅移除可明确归属的孤立字母；已有译文会提示核对段首词义，重新翻译或编辑该段后清除提示。与手工译文无法安全分离时保留完整原文并报告原因。
