# 文档结构、统一视觉 API 与排版验收

## 使用方式

版面识别、直接翻译、排版后的视觉验收统一使用「Agent 设置」中的 API 地址、模型、密钥与思考设置，默认模型支持图片输入，不额外发能力探测请求。
不下载或运行本地识别模型，不依赖 ONNX Runtime、NumPy 或 OpenCV。本机仍负责 PDF 字符提取、图片渲染、几何校验和成品 PDF 生成。
默认直接翻译仍为每批最多 3 段、3 并发，没有自动术语准备，也没有翻译审校、修订或复核链路。

首次翻译前，将原文页图片发送给同一翻译 API 识别正文、标题、图表和公式区域；结果与原始字符、字体及绘图几何交叉校验。
排版完成后，将每个有当前语言译文的页面的原文图和译文图发送给同一 API，检查漏字、截断、重叠、公式变化、图表遮挡、异常留白和样式变化。
视觉验收不评审措辞，不自动重写译文。已有说明中完整保留的区域会随请求提供，避免将安全回退误报成新丢失。

排版报告显示「视觉验收通过」「视觉验收发现问题」或「视觉验收未完成」。当前前端只有验收通过才自动更新导出 PDF；发现问题或请求失败时保留候选预览，并允许明确下载“候选 PDF（未通过验收）”，不覆盖之前的自动导出文件。
更换 API 设置后可重新排版；「重新排版」按钮可重试未完成的验收，成功页复用缓存。
模型和提示协议改变、源文件或页面输出改变时相应缓存失效，编辑其他页面不会重复验收未变页面。

OpenAI 兼容接口使用 Chat Completions 的 `messages[].content` 图片数组。自定义 HTTP 接口的 JSON 模板需使用结构化 `{{images}}` 或 `{{messages}}` 变量；响应仍按原 `response_path` 读取 JSON 对象或 JSON 字符串。
所有图片、相关原文与译文会发送到用户配置的接口，可能产生额外调用费用。密钥不写入文档结构或验收缓存。

## 结构与公式保护

- `pdf_document.py` 保存版本化页面、字符、区域、段落、局部样式、公式对象和图形障碍。坐标为未旋转、相对裁剪框的 PDF 点坐标，保留页面旋转矩阵及字符归属。
- `pdf_model.py` 使用当前翻译配置发送多模态请求，校验 JSON 类别、归一化边界和置信度，限制响应大小，并对临时网络／接口错误进行最多两次重试。视觉请求并发上限为 3。
- `pdf_translation.py` 构建无碰撞的公式与局部样式标记，校验每个公式身份和出现次数、样式起止配对，并恢复纯文本及译文结构。
- `pdf_visual_check.py` 对照原文和译文图片，校验问题类别、段落 ID、范围和状态一致性，逐页缓存有效结果。失败响应不缓存为成功。
- `pdf_layout.py` 共用结构信息、公式矢量资源和译文样式，沿用安全擦除、同栏重排、字符级字体回退、链接恢复及绘制机制。

源结构保存为 `.data/<id>/structure/<摘要>.json`；译文关系单独保存为 `structure/translations.json`；视觉验收结果保存于 `structure/visual-checks/`。
原始文字、段落 ID 和保存译文不被重新编号或自动改写。译文关系绑定原文、译文、语言和结构摘要；人工编辑立即失效。内部组合段落仍映射至已有 ID。
源结构缓存使用原始 PDF 摘要、页面、段落文本与几何、API 设置指纹和协议版本，不使用明文密钥。详细字符数据按页加载，内存缓存最多 8 页／16 MiB 序列化数据。

已有文档普通打开阅读不强制分析全文；再次翻译或排版时按需准备。程序结构标记不暴露在保存译文、编辑框或 Markdown 中。
批次中有效译文继续保存，异常段落沿用现有有限重试。纯公式不调用文字翻译。无法可靠保护的公式不直接发送不受保护的文本。
历史译文支持可确定的下标及点导数等价写法、数量一致的重复公式；无法可靠对应时完整保留原文并报告，旧译文仍可在段落视图查看。

局部粗体、斜体、颜色和上标与段落基础样式分离，缺字只按符号回退。段间距、标题间距和公式间距继续参考原文，保持图片、表格和有意留白。
扫描图像配隐藏 OCR 层时保留完整页面，避免重影；扫描件重建、OCR 识别和复杂表格全面翻译不在本轮范围内。

## 接口与兼容性

| 接口 | 用途 |
| --- | --- |
| `GET /api/layout-model` | 返回统一视觉 API 的使用说明，不返回密钥 |
| `GET /api/documents/{id}/structure` | 页面分析与视觉验收进度 |
| `POST /api/documents/{id}/structure` | 请求体包含当前 `agent`，准备并缓存结构 |
| `POST /api/documents/{id}/layout` | 附带当前 `agent`，生成候选 PDF 并执行视觉验收 |
| `POST /api/documents/{id}/layout/prewarm` | 附带当前 `agent`，提前排版；最终布局调用完成视觉验收 |

现有单段、批量翻译接口直接使用请求中的 `agent` 完成所需结构分析。
旧客户端缺少 `agent` 时保持几何排版兼容，但明确返回 `visual_check.status=unavailable`，不能当作已通过视觉验收。
写接口沿用本机令牌、同源检查与文档处理互斥。`/api/session` 增加 `document_structure` 能力标记。
排版引擎版本为 79，源结构版本为 5，译文结构与视觉验收版本为 1。旧缓存保留但不误用。
更新后需重启服务并刷新页面；本轮最终版本未增加运行依赖。

## 验证与实际边界

Windows／Python 3.12 下执行 380 项 Python、95 项 JavaScript、三类隔离浏览器和跨版式输出检查。
API 测试通过 HTTP 模拟传输验证同一地址／模型／认证、真实 PNG 的多模态请求形状、自定义模板、响应校验、缓存失效、视觉失败不自动导出及密钥不落盘。
浏览器验收覆盖统一 API 的版面准备、公式和样式保护、纯文本保存、视觉验收状态、PDF 显示、文档管理、引用与笔记。
这些验证不等于真实服务商的视觉判断质量；本轮未调用用户真实翻译 API，不声称所有模型均可正确识别或验收。

隔离样本按 PDF 摘要去重：1 篇已有完整译文的 8 页论文，4 份单页参考 PDF，8 份单双栏、四种旋转及非零裁剪框合成页面，共 13 份／20 页。
参考 PDF 使用原文作为译文检查重建，合成页面使用确定性译文，不能当作真实模型翻译质量证据。
最终 API 对照使用明确标记的 HTTP 模拟响应，验证流程与排版；人工查看渲染结果补充检查。
完整论文的已放置中文缺失、碰撞、间距、字体突变、正文误加粗、符号和链接检查均无新增报告项。
在模拟版面 API 返回空区域的对照中，原引擎替换 296 块／保留 83 块，新引擎替换 291 块／保留 88 块；额外 5 块因历史译文公式不能可靠对应而保留。
该结果验证安全回退与旧数据兼容，不证明真实视觉模型识别效果。隐藏 OCR 单页现在完整保留，不再叠印重影。
完整报告见 `tmp/api-structure-audit/report.json` 和 `tmp/api-layout-check/tmp/source-layout-audit/report.json`。
